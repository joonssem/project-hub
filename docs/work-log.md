# Project Hub 작업 기록

## 2026-10-16

### 방향 조사와 사용자 인터뷰 기록

- 블로그 사례와 교육 자료 모음·GitHub 관리·자동화·CMS 자료를 조사하고 [방향 검토·인터뷰](direction-review-2026-10-16.md)에 출처와 함께 정리했다.
- 사용자 우선순위는 내가 만든 프로젝트와 최신 실행 주소 관리다. 학생·동료 교사·연수별로 원하는 자료를 선택 배치하며, 외부 교육 도구도 링크로 소개한다.
- 현재 구현과 공개 데이터를 유지하고, 확정된 사용자 요구·제안·후속 인터뷰 질문을 구분했다.
- README와 PRD에서 새 문서로 연결했다. 기능 구현·데이터 계약·배포 설정은 변경하지 않았다.
- 다음 논의는 최신 주소의 기준, 대상별 묶음, 공개·관리 정보 범위, 편집 방식, 외부 자료 선정 기준이다.
- 이번 작업은 문서 변경이며 테스트·빌드는 실행하지 않았다. 커밋·푸시 결과는 완료 보고에서 안내한다.

## 2026-10-13

### 제품과 초기 구현

- 요구사항·MVP·PRD 작성. 실제 프로젝트 연결과 학생·교사 탐색을 최우선으로 결정했다.
- 정적 카드 포털, 대상별 공개·숨김, 검색·태그, 공개 활용 안내, 발표 프리셋을 구현했다.
- 관리자 로컬 편집·JSON 파일/붙여넣기 가져오기·내용 확인/내보내기·프리셋 순서 편집을 구현했다.
- 공개 데이터 검증·오류 안내·재시도·이미지 대체 표시·접근성 개선과 dist 빌드를 마련했다.
- 기존 검증 기록은 docs/qa/에 보관했다.

### 개발 방향 검토 후 보완

- [검토 보고](review-2026-10-13.md)에 기존 구현과 보완 사항을 구분했다.
- 저장소 URL과 실행 URL을 분리하고 개발·운영·점검·보관 상태를 공개 대상 설정과 독립적으로 추가했다.
- 미니게임 플랫폼 공개 저장소와 실제 실행 주소를 확인·등록했다. 게임 코드·DB·로그인 통합 없음.
- JSON version 2, 기존 v1 가져오기, JSON Schema, 향후 DB 매핑을 [데이터 계약](data-contract.md)에 정리했다.
- 직전 목록 복원 버튼과 v1/v2 데이터 보존 테스트를 추가했다.
- GitHub Pages 하위 경로 지원과 .github/workflows/pages.yml을 준비했다.
- iPad Safari를 위해 입력 글자 크기·터치 대상과 fetch 타임아웃 방식을 보완했다.
- 배포 후 수행할 [실제 iPad 테스트 항목](ipad-safari-test.md)을 작성했다.

### 검증 상태

- 검사·테스트 8개와 정적 빌드 통과.
- 미니게임 실행 홈에서 방 만들기·방 들어가기 확인. 게임 전체 흐름 재검증은 하지 않음.
- 새 저장소·상태 필드, 직전 목록 복원 UI와 Pages 하위 경로의 실제 브라우저 검증은 다음 작업으로 남음.
- 파일 선택 업로드·다운로드 완료 확인은 브라우저 자동화 제한으로 남음.
- GitHub Pages 실제 배포와 학생 iPad Safari 검증은 아직 미완료.

### 다음 시작점

1. GitHub 푸시 결과와 원격 main 상태를 확인한다.
2. GitHub Settings → Pages에서 배포 소스를 GitHub Actions로 설정하고 준비된 워크플로를 실행한다.
3. Pages URL에서 학생·교사·프리셋·대표 이미지·실행 링크를 검증한다.
4. 신규 메타데이터 편집과 직전 목록 복원, 파일 왕복을 확인한다.
5. 실제 학생 iPad Safari에서 테스트 표를 채운다.

오늘 종료 요청에 따라 추가 프로젝트 등록이나 백엔드 도입은 진행하지 않았다. Git 저장소를 초기화하고 공개 원격 저장소 `joonssem/project-hub`를 준비했다. 오늘 커밋에는 초기 구현 전체와 문서·검토 보완을 함께 포함한다. 커밋·푸시 성공 여부와 해시는 사용자 완료 보고에서 안내한다.
