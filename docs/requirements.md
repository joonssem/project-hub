# Project Hub 요구사항과 MVP

제품 우선순위와 출시 판단은 [PRD](PRD.md)를 기준으로 한다. 이 문서는 초기 구현의 화면·데이터 계약을 설명한다. 관리자 인증·웹 저장은 필요가 확인된 뒤 도입하며 현재 MVP의 필수 확장으로 보지 않는다.

설계 원칙: 프로젝트는 독립적으로 개발하고, 정보는 한곳에서 관리하며, 이용자에게는 필요한 것만 보여준다.

## 목적과 경계
허브는 프로젝트의 메타데이터와 실행 주소를 관리한다. 각 프로젝트는 기존 저장소, 배포, DB, 로그인을 유지한다. `D:\Projects\mini_game_platform`은 단일 카드로 등록하며 코드를 가져오거나 인증을 통합하지 않는다. 실제 배포 주소는 확인 전까지 비워 둔다.

## 화면
- 학생: 숨김이 아니고 학생 공개가 켜진 프로젝트. 검색과 태그 필터, 외부 실행 링크.
- 교사: 숨김이 아니고 교사 공개가 켜진 프로젝트. 수업 자료와 공개 활용 사례.
- 발표·연수: JSON에 정의된 프리셋의 순서대로 선택 프로젝트 표시. 숨김 프로젝트는 제외한다. 대상별 공개와 별도로 발표에 선정하는 것은 명시적인 공개 의사다.
- 관리자: 전체 카드 목록, 등록·수정, 숨김, 학생·교사 공개, 프리셋 편집, JSON 가져오기·내보내기. 인증 없는 로컬 편집 도구이며 보안 관리 페이지가 아니다.

## MVP 범위
의존성 없는 정적 HTML/CSS/JavaScript와 버전 관리 가능한 JSON. 대표 이미지(선택), 이름, 설명, HTTP(S) 실행 링크(선택), 태그, 공개 여부, 숨김, 공개 활용 사례를 관리한다. 이미지가 없으면 기본 그래픽을 표시한다. 미등록 주소는 실행 버튼을 비활성화한다. 입력값과 JSON 구조를 검증한다. 변경은 메모리에만 반영하며 JSON 내보내기 후 `data/projects.json`을 교체해야 영구 반영된다. 새로고침으로 미내보낸 변경을 잃을 수 있으므로 경고한다. URL의 view/preset 값으로 화면을 공유한다.

## 공개와 접근 제한
숨김과 대상 필터는 화면 표시 규칙이다. 공개 JSON과 관리자 화면은 누구나 읽을 수 있다. 비공개 프로젝트 정보·개인정보·비밀키·내부 메모를 JSON에 넣지 않는다. 실제 접근 제한은 개별 프로젝트 또는 향후 서버의 인증과 권한 검사로 구현한다. 브라우저 필터는 보안 경계가 아니다. 발표 프리셋에 넣은 정보 역시 공개 데이터다.

## 데이터 계약
최상위 `version: 2`, `projects`, `presets`. 프로젝트: 고유 `id`, `name`, `description`, `image`, 실행 `url`, 공개 GitHub `repositoryUrl`, 상태 `status`, 문자열 배열 `tags`, boolean `student`, `teacher`, `hidden`, 공개 문자열 `usage`. 프리셋: 고유 `id`, `name`, `description`, 기존 프로젝트 ID 배열 `projectIds`. 알 수 없는 필드는 거부해 비공개 메모가 우연히 포함되는 것을 줄인다. 이미지도 HTTP(S) 주소 또는 assets/ 내부 상대 경로만 허용한다. 이전 version 1 파일은 값 보존 후 새 필드 기본값을 추가한다. 자세한 규칙은 [데이터 계약](data-contract.md)을 따른다.

## 후속 단계
1. 운영 방식과 호스팅 결정, 실제 프로젝트 목록과 실행 주소 입력.
2. 관리자 로그인, 서버 권한 검사, 웹 저장·변경 이력. 비공개 데이터는 공개 응답과 별도 저장.
3. 피드백·활용 기록: 공개 동의, 개인정보 최소화, 보관 기간과 삭제 규칙을 먼저 결정.

## 완료 기준
대상 필터와 숨김, 검색·태그, 프리셋 순서가 일관되게 동작한다. 관리자가 카드와 프리셋을 편집하고 JSON으로 재가져올 수 있다. 잘못된 URL·중복 ID·비공개 필드가 거부된다. 모바일에서도 카드와 편집 폼을 사용할 수 있다.
