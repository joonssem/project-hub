# 공개 데이터 계약과 향후 이전

현재 원본 형식은 `version: 2`다. 형식 정의는 [JSON Schema](catalog.schema.json), 실제 실행 검증은 `src/catalog.js`가 담당한다. 스키마 외에도 URL 자격증명·상대 경로 탈출, ID 중복, 프리셋 참조의 존재 여부를 실행 검증에서 검사한다.

## 신규 필드

- `url`: 이용자가 실행할 HTTP(S) 주소. 저장소 주소와 혼용하지 않는다.
- `repositoryUrl`: 공개해도 되는 GitHub 저장소 주소 또는 빈 문자열. 비공개 저장소 주소는 넣지 않는다. 학생 화면에는 저장소 링크를 표시하지 않지만 공개 JSON에서는 누구나 읽을 수 있다.
- `status`: `development`(개발 중), `active`(운영 중), `maintenance`(점검 중), `archived`(보관). 상태는 표시·실행 링크를 자동 차단하지 않는다. 숨김·학생·교사 공개와 독립적으로 편집한다.

## 이전 파일과 데이터 보존

버전 1 파일을 가져오면 기존 ID·텍스트·실행 주소·태그·공개 설정·숨김·활용 안내·프리셋 순서를 보존한다. 새 필드만 `repositoryUrl: ""`, `status: "development"`로 추가한다. 내보내기는 버전 2로 수행한다. 지원하지 않는 버전과 알 수 없는 필드는 조용히 제거하지 않고 거부한다. UTF-8 BOM이 있는 JSON도 읽을 수 있다.

적용 전 데이터는 현재 탭의 직전 목록으로 보존한다. 직전 목록 복원은 한 단계 복원이며 버튼을 다시 누르면 두 목록을 오갈 수 있다. 새로고침 후에는 이 메모리 복원 기록이 사라진다. 영구 백업은 내보낸 파일 또는 Git 이력으로 보관한다. 복원 후에도 원본 파일 교체와 재배포가 필요하다.

## 향후 DB로 옮길 때

프로젝트 ID는 화면 이름과 독립적인 영속 키로 유지한다. `projects`는 프로젝트 테이블, `presets`는 프리셋 테이블, `projectIds`는 프리셋·프로젝트 연결과 순서 값으로 옮길 수 있다. 태그는 배열 또는 태그 연결 테이블로 옮긴다. enum 상태와 boolean 공개 설정은 서로 별도 컬럼으로 유지한다. 현재는 DB를 도입하지 않는다.

자료 저장소에 있던 코드·DB·로그인은 이전 대상이 아니다. 향후 비공개 메모가 필요해져도 현재 공개 테이블과 공개 응답에 그대로 필드를 추가하지 않는다.

## 공개 내용 검토

허용 필드와 타입 검증은 비공개 필드 추가를 막지만, 설명이나 활용 안내 안에 입력된 개인정보·비밀값까지 판단하지 못한다. 배포 전 작성자가 텍스트와 주소를 검토해야 한다. 현재 JSON은 프로젝트 설명·공개 주소·표시 설정만 포함하며 개인정보·비밀키·비공개 메모를 등록하지 않았다.
